# Agent Note: Built-in Tool Names and Session Compatibility

Status: implemented

## Problem

Cooper 的模型接口会供终端和桌面端共用。核心文件操作和命令工具需要易于辨认的名字，已有会话则包含升级前的工具调用名称和依赖请求前缀的协议续传数据。

## Decision

模型工具目录使用 `read`、`edit`、`write`、`shell`。这些名称对应常见工作区动作。名称需要说明资源或作用范围时使用限定词。MCP 服务器工具由服务器命名空间区分。

旧工具名作为分发层别名。别名与规范名解析到同一个工具，权限检查、进程授权和执行事件使用规范名。工具目录只声明规范名。历史保留模型原始调用名称、参数和调用 ID，适配器继续使用已有续传校验。 [协议续传](2026-11-12-reasoning-continuation-replay.md) · [工具与权限](../../../../docs/tools-and-permissions.md#工具命名)

## Alternatives considered

**同时向模型声明新旧工具。** 这样能在工具目录里保留旧入口，但每个动作会有两套定义，增加目录体积和选择歧义。

**升级时替换旧会话中的工具名。** 历史会看起来一致，但改写后会改变工具调用的协议内容，也破坏以原始调用为锚点的续传数据。

## Consequences

已有提示和旧模型调用可以通过别名执行。进程授权的粒度仍由解析后的工具决定。工具目录变化可能使升级前的缓存和前缀绑定续传失效，适配器按既有锚点规则处理。
