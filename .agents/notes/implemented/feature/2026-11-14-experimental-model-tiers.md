# Agent Note: Experimental Model Tiers

Status: implemented

## Problem

同一供应商可以提供多个模型，也可以为一个模型提供多档推理强度。原先 Cooper 只有一套模型参数。用户在对话中切换预算需要修改配置，旧会话 header 也只能记录创建时使用的模型。

## Decision

Seraphina、Cherubina 和 Thronia 是同一供应商连接上的三个可选档位。它们共享协议、地址和 API key。每档可以配置实际请求模型 ID、显示名称、推理强度、上下文和生成上限。多个档位可以指向同一个模型 ID，并使用不同的推理强度或预算。顶层 `model` 始终必填。选中缺失档位时，实际请求使用顶层模型和有效参数。TUI 同时标出档位和回退后的模型。

### 选择与配置

显式 `--tier` 优先于保存的档位，其次是 `defaultTier` 和隐式 Cherubina。没有档位定义或其他选择时直接使用顶层模型。档位及兜底的有效总窗口至少为 256,000 tokens。兜底模型沿用同一个下限，所以选择缺失的档位时仍能使用顶层模型。单模型配置沿用原有窗口规则。启用档位后，总窗口扣除有效输出预留，再应用现有安全阈值。输出上限显式大于默认预留时仍要为它保留空间。 [档位配置与协议字段](../../../../docs/providers.md#实验性模型档位)

TUI 空闲时可用 `/sera`、`/cher`、`/thr` 切换。重载配置会按当前档位重新解析。通过 `/clear` 开启新会话时，按当前配置重新选择默认档位。请求字段由对应适配器生成。显式配置的摘要模型使用基础请求参数。兼容端点的服务能力由端点校验，错误显示档位、模型和请求参数。 [配置重载](2026-11-12-reload-user-config.md) · [单一供应商配置](../architecture/2026-11-11-single-provider-configuration-source.md) · [Provider routes 提案](../../proposed/architecture/2026-11-13-provider-routes-key-the-llm-adapter.md)

### 有效历史与缩窗

切换前按目标适配器实际会重放的输入估算预算。已有历史能装入目标窗口时直接应用。超限时 TUI 显示当前估算和目标上限，用户可确认压缩或取消。压缩使用历史副本，保留最近的可见消息组及工具调用和结果配对。持久会话在确认、预算校验和追加式 checkpoint 写入成功后才应用新档位。关闭持久化时，在内存中同时应用档位和有效历史。取消、压缩停用或压缩后仍超限时，原档位和有效历史仍可用。恢复与重载涉及档位历史的变更时同样检查目标预算。Headless 在发送请求和追加会话记录前报告超限。

直接切档追加 `model-selection` 记录，压缩切档使用包含有效历史和选择的同一条 checkpoint。选择中的 `tier: null` 表示使用顶层模型，旧会话缺少整条选择记录时才按启动默认值解析。恢复会话时以当前配置解析已保存的档位。如果该档位的定义被移除，继续使用该档位名称并回退到顶层模型。请求模型或预算发生变化时，宿主显示该变化。会话保存模型选择和预算，API key 留在用户配置中。 [会话记录与恢复](../../../../docs/context-and-sessions.md#持久化与恢复)

### 请求前缀与续传

切档状态由宿主显示。显示名称只用于界面，协议续传身份使用实际请求模型 ID。已有历史适合目标预算时，保留原消息、系统提示和工具定义。适配器只重放与当前协议、端点、请求模型和锚点匹配的 continuation。恢复相同档位可保留复用前缀的条件，命中仍由供应商缓存决定。 [现有续传约定](../architecture/2026-11-12-reasoning-continuation-replay.md)

## Alternatives considered

**自动选择任意已配置档位。** 可减少兜底使用，但增删档位可能意外改变请求模型和代价。固定默认规则让选择可预测。

**仅改变模型的推理强度。** 可复用同一模型，但不覆盖用户需要另一个模型 ID、上下文或生成预算的场景。

**每档独立连接。** 能跨服务切换，也会改变对话数据的接收方。这个实验以同一连接上的模型选择为范围。

**恢复时重新选启动默认档。** 实现较少，但容易将已有对话发送到另一个模型并失去已有前缀的复用机会。

## Consequences

用户可以在同一会话中调整模型与预算。压缩后切回较大窗口继续使用已经压缩的有效历史。恢复时更改档位定义会改变实际请求参数。供应商模型的强度和输出支持仍取决于部署和服务规格。

## Verification

[档位测试](../../../../apps/cli/test/model-tiers.test.tsx)覆盖默认与回退、256K 窗口下限、三个协议的参数、摘要模型隔离、300K → 256K 的确认与取消、压缩后切回大档、无法缩窗时保留末尾可见组、无头超限保持会话文件，以及中断后恢复最后一份完整档位和有效历史。测试通过模拟端点检查请求字段。
