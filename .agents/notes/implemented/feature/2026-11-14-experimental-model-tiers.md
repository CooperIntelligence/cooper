# Agent Note: Experimental Model Tiers

Status: implemented

## Problem

同一供应商可以提供多个模型，也可以为一个模型提供多档推理强度。原先 Cooper 只有一套模型参数。用户在对话中切换预算需要修改配置，旧会话 header 也只能记录创建时使用的模型。

## Decision

Seraphina、Cherubina 和 Thronia 是同一供应商连接上的三个可选档位。它们共享协议、地址和 API key。每档可以配置实际请求模型 ID、显示名称、推理强度、上下文和生成上限。顶层 `model` 始终必填。选中缺失档位时，实际请求使用顶层模型和有效参数。TUI 同时标出档位和回退后的模型。

### 选择与配置

显式 `--tier` 优先于保存的档位，其次是 `defaultTier` 和隐式 Cherubina。没有档位定义或其他选择时直接使用顶层模型。档位及兜底的有效总窗口至少为 256,000 tokens。单模型配置沿用原有窗口规则。启用档位后，总窗口扣除有效输出预留，再应用现有安全阈值。输出上限显式大于默认预留时仍要为它保留空间。

TUI 空闲时可用 `/sera`、`/cher`、`/thr` 切换。重载配置会按当前档位重新解析。新会话使用启动默认档位。请求字段由对应适配器生成。显式配置的摘要模型使用基础请求参数。兼容端点的服务能力由端点校验，错误显示档位、模型和请求参数。 [配置重载](2026-11-12-reload-user-config.md) · [单一供应商配置](../architecture/2026-11-11-single-provider-configuration-source.md) · [Provider routes 提案](../../proposed/architecture/2026-11-13-provider-routes-key-the-llm-adapter.md)

### 有效历史与缩窗

切换前按目标适配器实际会重放的输入估算预算。已有历史能装入目标窗口时直接应用。超限时 TUI 显示当前估算和目标上限，用户可确认压缩或取消。压缩使用历史副本，并保留工具调用和结果配对。确认、预算校验和追加式 checkpoint 写入都成功后才应用新档位。无法完成时原档位和有效历史仍可用。Headless 在发送请求和追加会话记录前报告超限。

直接切档使用模型选择记录，压缩切档使用包含完整有效历史和选择的同一条 checkpoint。恢复会话后以当前配置解析已保存档位，若请求模型或预算发生变化，宿主显示该变化。会话保存模型选择和预算。API key 留在用户配置中。

### 请求前缀与续传

切档状态由宿主显示。消息历史、系统提示和工具定义继续按现有机制构建。适配器只重放与当前协议、端点、请求模型和锚点匹配的 continuation。恢复相同档位可保留复用前缀的条件，命中仍由供应商缓存决定。 [现有续传约定](../architecture/2026-11-12-reasoning-continuation-replay.md)

## Alternatives considered

**自动选择任意已配置档位。** 可减少兜底使用，但增删档位可能意外改变请求模型和代价。固定默认规则让选择可预测。

**仅改变模型的推理强度。** 可复用同一模型，但不覆盖用户需要另一个模型 ID、上下文或生成预算的场景。

**每档独立连接。** 能跨服务切换，也会改变对话数据的接收方。这个实验以同一连接上的模型选择为范围。

**恢复时重新选启动默认档。** 实现较少，但容易将已有对话发送到另一个模型并失去已有前缀的复用机会。

## Consequences

用户可以在同一会话中调整模型与预算。压缩后切回较大窗口继续使用已经压缩的有效历史。恢复时更改档位定义会改变实际请求参数。供应商模型的强度和输出支持仍取决于部署和服务规格。

## Verification

自动化测试覆盖默认与回退、256K 窗口下限、三个协议的参数、摘要模型隔离、300K → 256K 的确认与取消、headless 持久状态保护，以及中断后恢复同一档位和有效历史。协议参数使用模拟端点验证。
