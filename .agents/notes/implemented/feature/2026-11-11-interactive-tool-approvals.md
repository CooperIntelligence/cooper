# Agent Note: Interactive Tool Approvals for 0.1.0-rc.1

Status: implemented

## Problem

旧审批面板在 `80×24` 的终端里只显示 40 行新增内容的前 12 行。只补末尾换行或把 CRLF 转为 LF 时，面板会显示 `No changes.`，即使写入会改变文件字节。

审批等待期间，外部编辑可能改变替换的位置，目录链接改指向也可能改变命令的实际工作目录。旧面板按一次 `a` 就授权同一工具的后续调用，`/reload` 更换实际 shell 后仍沿用授权。终端历史只显示工具结果，用户难以区分手动批准和沿用进程授权。

## Decision

### 让预览对应实际操作

文件 diff 和完整命令按终端高度分页，长行换行，命令预览显示实际 shell 和解析后的工作目录。预览将终端控制字符转为可见文本，区分内容相同、新建空文件和行尾变化。大文件或 MCP 工具无法提供完整效果预览时，面板标明预览不可用并保留操作摘要。

收到批准后，文件工具复核实际目标、存在状态和字节内容，命令工具复核解析后的工作目录。发生变化时，旧批准和待授予的进程权限一并失效。能生成新预览时重新询问，目标失效时报告错误。命令启动前再次核对工作目录，发现变化即报错。[工作区真实路径约束](../bug-fix/2026-11-11-workspace-real-path-containment.md)

### 明确授权范围和生效时机

单次批准只需按 `y`。按 `a` 会打开二次确认页，说明授权覆盖当前调用和同一工具在本进程中的后续调用，后续参数可以不同。确认页按 `Esc` 返回预览。两页均用 `n` 拒绝，`Enter` 无审批动作。

工具授权随进程结束而失效，在同一进程切换对话或重载相同 shell 时继续有效。成功应用配置后，如果实际 shell 类型或可执行文件路径发生变化，只撤销 `run_command` 的授权，因为相同命令在不同 shell 中可能有不同效果。`PermissionPolicy` 执行权限规则，`plan` 和无交互的 `ask` 拒绝受管控工具。[运行时权限模式](2026-11-09-runtime-permission-modes.md) · [进程级自动授权](2026-11-11-per-process-auto-authorization.md) · [命令 shell](2026-11-11-configurable-command-shell.md) · [配置重载](2026-11-12-reload-user-config.md)

### 让终端历史还原用户决定

终端历史分别记录手动批准与执行结果，沿用进程授权的调用在结果行标注来源，拒绝只留一条记录。审批决定的可回看范围由终端滚动历史决定，会话继续保存工具结果。

## Alternatives considered

**保留一屏截断。** 实现简单，面板高度也容易控制。隐藏行数无法告诉用户被省略的内容是什么。分页的代价是预览可能需要多次按键，收益是可在批准前查看完整效果。

**目标变化后沿用旧批准。** 省去重新预览和确认的代价是，写入可能覆盖不同内容，命令可能在另一个目录执行。

**一次按 `a` 就放行，并按工具名保留到退出。** 这是旧面板的行为。它省一次按键，也把当前调用和参数不同的后续调用合在同一个动作里。二次确认把这个范围说清楚。单次批准仍只需一次按键，换 shell 时只重新询问受影响的命令工具。

**无法生成预览时直接拒绝。** 会阻断大文件和许多本来就没有效果预览的 MCP 工具。明确显示预览缺失和操作摘要，让用户可以在 `ask` 模式下自行决定。

## Consequences

复核需要再次读取文件或解析目录。等待期间反复修改目标可能触发多次确认。最后一次核对与实际写入或启动进程之间仍有文件系统竞态。

进程内工具授权以工具名为粒度，覆盖同一工具的其他参数。按路径或命令授权需要独立决策。

## Verification

Windows ConPTY 和 Linux PTY 的 `80×24` 会话均验证了文件 diff 与长命令可以翻到末尾，批准后写入，拒绝后跳过执行，以及已完成回复只进入滚动历史一次。Linux PTY 另验证了缩放后继续翻页。Windows Terminal 图形前端已通过人工复核。

自动化回归覆盖了文件预览失效、目录链接改指向后的重新确认，以及预览复核后目录再次改变时拒绝启动命令。
