# Agent Note: Interactive Tool Approvals for 0.1.0-rc1

Status: proposed

## Problem

在 `ask` 模式下，用户需要在执行前看清 Cooper 即将做什么。当前审批面板与普通运行状态同时显示，长 diff 只展示开头和省略行数。`always allow` 也容易被理解成永久授权、当前对话授权，或仅授权当前路径和命令。操作结束后，用户需要能从终端历史里区分自己的审批决定和工具执行结果。

## Proposal

将每个待审批的工具调用呈现为一个独立的等待状态。显示「等待批准」时暂停普通运行提示，由审批面板接管操作键。每个面板对应一次工具调用。

- **文件修改**显示路径、增删行数和 diff。按终端高度分页，支持键盘翻页和长行换行。无法生成预览时显示「无法预览」和操作摘要。有预览且内容相同时显示「无改动」。
- **命令执行**显示完整命令、所用 shell 和工作目录。长命令可换行或分页，用户能读到管道、重定向和后续子命令。
- **MCP 调用**显示服务器、工具名和可用的调用摘要。工具未提供效果预览时，面板明确说明。

### 交互示例

```text
Waiting for approval · Edit file
apps/cli/src/session-view.ts                         +8 −3

@@ -42,5 +42,6 @@
-  return replayAll(messages)
+  return replayCompleted(messages)

Page 1/3 · ←/→ to browse
y Allow once · a Allow this tool until exit… · n/Esc Deny
```

- `y` 允许当前调用。后续调用仍由现有权限策略判断。
- `a` 先显示工具名和授权范围，再要求确认。例如「退出 Cooper 前，后续 `run_command` 调用可在 Ask 模式下直接执行，包括其他命令」。确认页用 `y` 授权，`Esc` 返回预览，`n` 拒绝本次调用。
- 在预览页按 `n` 或 `Esc` 拒绝本次调用。两个页面都要求使用明确的动作键，`Enter` 不会批准。

### 授权边界与终端历史

沿用 [运行时权限模式](../../implemented/feature/2026-11-09-runtime-permission-modes.md) 和 [进程级自动授权](../../implemented/feature/2026-11-11-per-process-auto-authorization.md) 的边界。`a` 授权整个工具，持续到当前 Cooper 进程退出。同一进程内新建或切换对话后，授权仍有效。新进程从空的工具授权开始。`PermissionPolicy` 仍负责执行权限判断。

面板关闭后，在终端滚动历史中记录操作目标和用户决定，例如「已允许一次 · 运行 npm test」。工具结束时再显示执行结果，例如「执行失败 · exit 1」。拒绝的调用只留下拒绝记录。RC1 的审批记录限于当前终端历史，保存会话和恢复视图沿用现有协议。

审批翻页只更新待审批视图。流式回复的完成行仍一次性追加到 `Static`。翻页、缩放和面板收起时，终端历史中的完成行保持单份。

## Alternatives considered

**保留一屏截断预览。** 固定上限能控制面板高度，但剩余行数无法帮助用户判断被省略的改动。分页保留屏幕空间，也让用户能在批准前检查完整内容。

**按一次 `a` 直接允许该工具。** 按键次数更少，但这一步同时为参数不同的后续调用授权。二次确认提供了阅读授权范围的机会，单次批准仍只需按一次键。

## Acceptance criteria

- 在 Windows Terminal 和至少一个 macOS 或 Linux 终端的 `80×24` 窗口中，多页 diff 和长命令均可完整查看。翻页或缩放时，目标、页码和审批按键仍可见。
- `y` 只放行当前调用。`a` 在二次确认前不会放行，确认后授权仅适用于指定工具和当前进程。`Enter` 不会批准。`Esc` 能从确认页返回预览，也能在预览中拒绝当前调用。
- 缺少预览时仍可读到操作摘要。命令审批能看到传入 shell 的完整命令，以及实际工作目录或可无歧义解析它的工作区路径和相对路径。
- 终端历史可区分「已拒绝」「已允许，执行成功」「已允许，执行失败」。翻页、取消和执行结束后，流式完成行没有重复。
- `plan` 仍拒绝写入和执行，headless `ask` 仍拒绝受管控工具。同进程切换对话保留已授予的工具权限，新进程以 `ask` 恢复会话时重新询问。

## Risks

窄终端上的换行会挤占按键提示空间。分页先为操作目标、页码和按键保留行数，再分配预览行。命令与 diff 中的终端控制字符需要可见化，以免工具内容改写界面。

按工具授权的范围依然较广，尤其是 `run_command`。二次确认让范围可见，按命令或路径授权留待后续评估。终端历史可回看当前交互，跨进程审批审计留待后续评估。
